# Neo Solidity 编译器与 DevPack 技术加固 PRD

## 1. 项目信息

| 项目 | 内容 |
|------|------|
| **语言 / 地域** | 中文为主，代码标识保留英文 |
| **原始需求** | 对 Neo Solidity 编译器及 DevPack 进行「全面审计、优化、迭代、重构」，使其功能完整、代码专业、体验友好、覆盖全面。 |
| **项目简称** | **Neo Solidity Hardening（NSH）** |
| **版本基线** | 当前主版本 v0.30.x，已完成架构分层与宏/错误处理清理 |
| **范围边界** | Rust 编译器本体（src/*）+ TypeScript 工具链（tooling/packages/*）+ DevPack 运行时与合约模板 |

---

## 2. 产品定义

### 2.1 目标

1. **稳定性优先**：消除关键路径上的 unwrap/expect、panic 与未处理错误，建立可预测的错误模型；编译器不应因合约写法或环境差异直接崩溃。
2. **可维护性升级**：完成 >800 行大文件的外科式拆分，统一模块边界、命名约定与错误码体系，使新贡献者能快速定位代码。
3. **端到端可用**：补齐 neo-forge build、运行时覆盖与工具链模板版本一致性，开发者能「开箱即用」完成编译、测试、部署。

### 2.2 用户故事

| 角色 | 故事 | 成功标准 |
|------|------|----------|
| **Solidity 合约开发者** | 作为合约开发者，我希望用标准 0.8.19–0.8.27 Solidity 语法编写合约后，通过 `neo-forge build` 直接得到 NEF + Manifest，且报错信息能指出具体行号和原因。 | `neo-forge build` 可完整执行；错误信息包含文件、行、列、可操作建议。 |
| **工具链用户** | 作为 Hardhat/Foundry 用户，我希望初始化模板默认使用与编译器一致的 Solidity 版本，无需手动回退 0.8.34，并且集成测试能通过。 | 模板版本与编译器支持范围一致；集成测试 CI 通过。 |
| **维护者** | 作为核心维护者，我希望单文件长度控制在 800 行以内，模块职责单一，新增 pass/优化器可独立测试。 | 无 >800 行核心文件；新增模块单测覆盖 ≥80%。 |
| **运行时贡献者** | 作为 DevPack 贡献者，我希望 runtime 与合约 API 的存根都有明确实现计划，避免重复踩坑。 | 所有 stub 标注 TODO + issue 链接或已替换为真实实现。 |
| **QA / 审计人员** | 作为审计人员，我希望关键路径有完整的单元测试、集成测试与错误码回归测试，能自动拦截回归。 | CI 覆盖 unit / integration / clippy / doc；回归测试清单可运行。 |

## 3. 技术规范

### 3.1 需求池

#### P0 — 必须在本轮完成（阻塞发布）

| 编号 | 类别 | 需求 | 关联上下文 |
|------|------|------|------------|
| P0-1 | 审计 | 完成编译器全链路错误处理审计：消除前端/parser → IR → codegen → manifest 各阶段关键路径上的 unwrap/expect；所有错误通过 `fatal_error!` 或结构化 `CompilerError` 统一输出。 | v0.30.2 已处理部分 unwrap/unsafe/docs，但运行时/工具链仍有残留 |
| P0-2 | 优化 | 修复 Solidity 版本一致性：工具链模板默认版本需与编译器支持范围（>=0.8.19 <0.8.28）严格一致，移除 0.8.34 默认配置。 | 模板当前默认 0.8.34，导致编译失败 |
| P0-3 | 重构 | 对剩余 >800 行核心文件进行外科式拆分，确保每个文件单一职责、命名清晰，并保留 git 历史可追溯。 | 已拆分 v0.30 但仍存在多个大文件 |
| P0-4 | 重构 | 补齐 `neo-forge build` 的完整实现，包括 CLI 入口、配置解析、编译调用、产物输出与基本错误报告。 | 当前未实现，阻塞 Foundry 用户 |
| P0-5 | 测试 | 为 P0-1 / P0-4 建立回归测试：错误输入必须产生非 panic 退出；neo-forge build 在示例项目上能产出正确 NEF。 | 验收标准见 3.2 |

#### P1 — 高优先级（本轮尽量完成）

| 编号 | 类别 | 需求 | 关联上下文 |
|------|------|------|------------|
| P1-1 | 审计 | 对 optimizer 与 codegen 的 pass 进行覆盖率审计，补充缺失的边界 case（空合约、超大字面量、异常分支）。 | 优化器存在边界条件 stub |
| P1-2 | 优化 | 统一运行时/库 API 的命名与版本兼容性标记，减少 Solidity 开发者心智负担。 | runtime/devpack 覆盖仍有 stub |
| P1-3 | 重构 | 将重复的错误格式化逻辑抽取到单一模块，所有阶段错误共享诊断结构（Diagnostic）。 | 当前错误信息分散在各阶段 |
| P1-4 | 用户体验 | 改进编译错误输出：显示源码片段、建议修复、错误码（NSH-XXXX）。 | 现有输出为纯文本，可读性一般 |
| P1-5 | 测试 | 建立集成测试矩阵（不同 Solidity 版本、不同 OS、不同工具链入口）。 | 集成测试包存在但覆盖不足 |

#### P2 — 中低优先级（后续迭代）

| 编号 | 类别 | 需求 | 关联上下文 |
|------|------|------|------------|
| P2-1 | 审计 | 文档与代码注释审计：所有 `unsafe` 块必须有安全论证；所有 `TODO` 必须关联 issue 或转化为 P0/P1。 | 文档与 unsafe 标注需完善 |
| P2-2 | 优化 | 性能基准：针对大合约（>10K 行）测量编译时间与内存占用，识别并优化瓶颈 pass。 | 无当前性能基线 |
| P2-3 | 重构 | 将 codegen 与 manifest 之间的产物格式抽象为独立 crate，便于未来支持其他后端。 | 当前耦合度较高 |
| P2-4 | 用户体验 | 提供 VS Code / 编辑器扩展建议与 LSP 初版诊断接口。 | 无 LSP 支持 |
| P2-5 | 测试 | 模糊测试（fuzz）：对 parser 与 IR 转换输入随机 Solidity 片段，验证不 panic。 | 安全加固方向 |

### 3.2 验收标准

| 编号 | 验收项 | 检查方式 |
|------|--------|----------|
| AC-1 | `cargo build` 与 `cargo test` 在 stable Rust 最新版上通过。 | CI 运行 |
| AC-2 | `cargo clippy -- -D warnings` 与 `cargo doc` 无告警。 | CI 运行 |
| AC-3 | 任意包含语法/语义错误的 Solidity 输入，编译器以非零退出码退出并输出结构化错误（含文件路径、行列、错误码）。 | 回归测试 |
| AC-4 | 工具链模板（neo-foundry、templates）默认 Solidity 版本在 [0.8.19, 0.8.28) 范围内。 | 配置文件检查 + 集成测试 |
| AC-5 | `neo-forge build` 在示例 Foundry 项目上成功生成 `.nef` 与 `.manifest.json`。 | 端到端测试 |
| AC-6 | src 下不存在 >800 行的核心文件（测试文件、生成文件除外）。 | 脚本检查 |
| AC-7 | 所有 `unwrap`/`expect` 仅在明确标注 `SAFETY:` 或不可能失败的上下文中使用；新增关键路径必须通过结构化错误处理。 | 审计报告 + clippy |
| AC-8 | 单元测试覆盖率：新增/重构模块 ≥80%；集成测试通过全部 P0 场景。 | 覆盖率工具 + 测试运行 |
| AC-9 | PRD 中 P0 项全部完成或记录合理推迟理由（由技术负责人确认）。 | 任务清单核对 |

## 4. 附录

### 4.1 参考范围

- Rust 源码：`src/frontend/`, `src/solidity/`, `src/ir/`, `src/codegen/`, `src/optimizer/`, `src/manifest/`, `src/cli/`, `src/neo/`, `src/runtime/`
- TypeScript 工具链：`tooling/packages/neo-foundry`, `tooling/packages/templates`, `tooling/packages/hardhat-solc-neo`, `tooling/packages/integration-tests`
- DevPack 合约：`devpack/contracts/`

### 4.2 版本与基线

- 编译器支持 Solidity 版本：`>=0.8.19 <0.8.28`
- 已完成功能：v0.29 架构提取；v0.30 文件拆分；v0.30.1/0.30.2 错误处理与文档清理

### 4.3 术语表

- **NEF**：Neo Executable Format，NeoVM 字节码容器。
- **Manifest**：合约元数据，包括 ABI、权限、信任等。
- **DevPack**：面向 Solidity 开发者的库与运行时支持包。
- **neo-forge**：计划中的 Neo 版 Foundry 构建工具。
